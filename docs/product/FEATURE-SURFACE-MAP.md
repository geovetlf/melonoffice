# MelonOffice: feature surface map

- Date: 2026-09-29, audited on main `f3c4366` (PR #89 merged).
- Rule (Geovet, 2026-09-29): a capability is **COMPLETE** only when all of these exist: backend, API, permissions, business logic, a UI entry point, a user action, and feedback for result, error, loading and empty. Backend alone never counts.
- How it was audited:
  - every API route in `apps/api/src` (115 routes, with its permission);
  - every web client in `apps/web/src`;
  - the pages in `apps/web/src/shell/routes.ts`.

  A route counts as surfaced only when a web client calls it from a page.

Statuses:

- `COMPLETE`
- `PARTIAL`: some actions are in the UI, others are not.
- `BACKEND_ONLY`: API and logic exist, with no UI.
- `ENGINE_ONLY`: a package with no API. It is used by other engines.
- `ARCHITECTURE_ONLY`: contracts or types only.
- `MISSING`
- `BLOCKED`: waiting on a decision, credential or apply.

Today every permission belongs to the one role, `owner` (ADR-0019). Roles beyond owner are decision D-27, still open.

## 2. Backend-only by design

These have no screen on purpose, because a person never acts on them directly:

- Brain `context` (assembled for GIA);
- events outbox and bus;
- jobs and leases;
- webhooks;
- the platform usage report (an operator CLI, never a tenant route);
- Decision Engine types.

## 3. Placeholders still in the UI

These must never pass for real data:

- **Home "Today's tasks" and "Meetings"** are example data with an "Example" badge. Tasks should come from real agent tasks. Meetings wait for a calendar.
- **Home quick actions, and the GIA bar's attach and voice buttons**, are marked "Soon".
- **Seat actions** (assign, move, remove) are "Soon". They need a seating permission decision (ADR-0041).
- **Department "coming" areas** are "Soon".
- **Sidebar tools** (projects, calendar, communications, apps) are "Soon".

## 4. Order to close the gaps

Each block is one PR, reusing existing engines only:

1. **AI usage and cost page.** It uses the existing ledger API and its UI is missing. It shows internal cost and customer credits apart, by capability, provider, model, department, agent and workflow, and it is opened from the Home credits panel.
2. **Approval center.** One list of every pending approval, from the existing `approvals` API.
3. **Agent lifecycle.** Create, edit, activate, pause and archive, from the existing specialists API, plus an agent page with skills, tools, version and capabilities.
4. **Workflow management.** Create, version, pause and archive in Automations, from the existing API.
5. **AI providers (read only).** A new read API over the registry, showing status, models, environment, price source and health.
6. **Tools and skills catalogue** views.
7. **Company Brain gaps**, and WhatsApp templates in Connections.
8. **Home, real data.** Real tasks replace the example panel, and there is a Ctrl+K command bar for GIA.
9. **AI Command Center**, built over 1, 2, 3 and 5.
