# MelonOffice: feature surface map

- Date: 2026-09-29. This is the second UX audit, on main `ab5f62b` (PR #90 merged) plus this PR.
- Rule (Geovet, 2026-09-29): a capability is **COMPLETE** only when all of these exist:
  - backend, API and permissions;
  - business logic;
  - a UI entry point and a user action;
  - feedback for result, error, loading and empty.

  Backend alone never counts.

- Audience rule (Geovet, 2026-09-29 19:49Z, ADR-0082):
  - AI providers, models, routing, health and internal cost belong to the **platform administrator** only.
  - Companies see credits and usage by capability, department, agent, workflow and task.
- How it was audited:
  - all 118 API routes in `apps/api/src` were listed and each one matched to the web client and page that calls it;
  - every screen was opened on desktop (1280 px) and phone (390 px) over the test backend, checking horizontal overflow and runtime errors;
  - every state was checked against the page's tests.

Statuses:

- `COMPLETE`
- `PARTIAL`: some actions are in the UI.
- `BACKEND_ONLY`
- `ENGINE_ONLY`: a package with no API.
- `BY_DESIGN`: no screen on purpose; the reason is given.
- `MISSING`
- `BLOCKED`: waiting on a decision, credential or apply.

Today every permission belongs to the one role, `owner` (ADR-0019). Roles beyond owner are decision D-27, still open.

## 3. States and devices

- Every screen has loading, empty, error and permission-denied states. Processing and pending states are covered too:
  - the "working" state of tasks and plans;
  - "waiting for your approval".
- Success is shown in place: an answer, a status change, a notice.
- Screens were checked at 1280 px and 390 px. None scrolls the page sideways.
  - Wide tables in `/platform` scroll inside their own box.
  - The bell's panel fits a phone.
- No console or runtime errors on any audited screen.

## 4. Placeholders still in the UI

Each of these is visibly marked, never presented as working:

- **Seat actions** (assign, move, remove) are "Soon". They need a seating permission decision (ADR-0041).
- **The GIA bar's voice button** is dimmed and says "soon".
- **Department "coming" areas** are "Soon".
- **Sidebar tools** (projects, calendar, apps) are "Soon".

Removed in this audit:

- The Home quick actions for tools that do not exist (document, email, meeting, video, more). They are replaced by shortcuts to real screens, shown by permission.
- The disabled bell. It is now real.
